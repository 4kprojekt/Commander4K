# `*.c4k` Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the per-folder `c4k.dir` with any number of `*.c4k` item files: one file = that item's view, several = an automatic dashboard sorted by file name.

**Architecture:** A new Core model (`C4kItem` per file, `C4kFolder` per folder, `C4kReader`, `C4kWriter`, `C4kTrustStore`) is added next to the old one, then the Built-in dashboard layer, the App and MCP are moved onto it, then the old types are deleted. The old `FolderConfig`/`FolderAction`/`FolderTile`/`FolderConfigWriter`/`FolderTrustStore` live until Task 9.

**Tech Stack:** .NET 10, Avalonia (C# only), System.Text.Json, xunit.v3 (`dotnet test --solution Commander4K.sln`), PowerShell catalog plugins.

**Spec:** `docs/superpowers/specs/2026-11-08-c4k-files-design.md` (read its "Calls made after the builder check" section: it fixes behaviour this plan only references).

## Global Constraints

- `TreatWarningsAsErrors` is on: any warning fails the build.
- No I/O on the UI thread; reads go through `VfsRouter`/`IPluginHost`; abandonable network calls keep `.WaitAsync(ct)`.
- Every user-visible string goes through `Loc.T(...)` with an entry in `src/Commander4K.Core/Localization/i18n/en.json` (`LocalizationTests` fails on missing/stale keys). Polish is the key.
- Item file: JSON with comments and trailing commas allowed, at most `256 * 1024` bytes, extension `.c4k` (case-insensitive), at most 50 items per folder, folder listing limit 2 s, only on file/smb/sftp/ftp.
- Dashboard order = natural, case-insensitive sort of the file name. No `order`, no heading tiles, no ↑↓/× on cards; ⤢ resize stays.
- No migration and no reader for `c4k.dir`.
- No new AI features; MCP tools/prompts only.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Tasks 4–6 break the solution build (the dashboard types change under the App). Verify those tasks per project as written; the whole solution builds again at the end of Task 6. Keep the old Core types untouched until Task 9.
- There is no App test project: App steps are checked by build + the listed manual run (`dotnet run --project src/Commander4K.App`), and the plan says so each time.

## Review Focus

1. The hidden folder `.thumbnail.c4k` (gallery thumbnails) and dot-files must never count as items (Task 1 test).
2. Names sort naturally and ignoring case: `2-a.c4k` before `10-a.c4k`, `B.C4K` among `a.c4k` (Task 1 test).
3. More than 50 files: first 50 used, `Skipped` reports the rest, dashboard shows a notice card (Tasks 1 and 4).
4. One broken file among several: that card shows its error, the others work; a single broken file shows the error, not "no view" (Tasks 1 and 4).
5. Resizing a locked `run`/`ssh`/POST card must not revoke trust; renaming or editing `run` must (Task 2 test).
